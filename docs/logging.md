# Логирование

Приложение использует Loguru. Настройка находится в
`rfc-system-app/logging_config.py` и выполняется при загрузке `main.py`.

Логи выводятся в stderr: их можно читать через `docker compose logs -f`.
Файлы внутри контейнера не создаются; хранение и ротацию настраивает Docker.
Уровень задаётся переменной окружения `LOG_LEVEL`, по умолчанию `INFO`.
Для диагностики подключений и SQL-операций можно выбрать `DEBUG`.

Уровни:

- `DEBUG`: открытие подключения, выполнение INSERT до commit.
- `INFO`: запуск и остановка, успешные запросы, вход, выход, commit регистрации.
- `WARNING`: неверные данные, отказ в доступе, конфликт email, HTTP 4xx.
- `ERROR`: сбой БД, необработанная ошибка, HTTP 5xx.

Каждый HTTP-запрос получает сгенерированный `request_id`. Он выводится
во всех логах внутри обработки запроса и в заголовке ответа `X-Request-ID`.
Вне запроса вместо ID выводится `-`. Время HTTP-запроса измеряется до
получения объекта ответа; передачу streaming body оно не измеряет.

Логи HTTP содержат шаблон маршрута, метод, статус и длительность.
Тела запросов, cookies, JWT, пароли, email, query string и SQL-параметры
не записываются. Ошибки PostgreSQL содержат SQLSTATE, неожиданные ошибки —
имя класса исключения. Текст исключений и локальные переменные намеренно
не выводятся: они могут содержать пользовательские данные.

При запуске Uvicorn можно отключить его отдельный access log:

```powershell
cd rfc-system-app
..\venv\Scripts\python.exe -m uvicorn main:app --no-access-log
```

Системные сообщения Uvicorn используют собственное стандартное логирование.
Настройка Loguru их не перехватывает.

Успешное создание заявки нужно логировать на уровне INFO после commit
в сервисе, когда реализация сохранения заявки будет завершена. Сообщение
об исполнении INSERT на уровне DEBUG ещё не означает сохранение транзакции.
